Design handoff

How the approved V4.4 language is built: typography, colour, spacing, components, responsive rules and interaction patterns, for the public journal and the private writing studio.

01

Principles

  • Black ink on white paper. The only colour on any page comes from album artwork and artist photographs, shown as they are: no filters, tints or overlays.
  • Kalam carries identity: titles, track names, notes and the closing line. There is no logo or wordmark in the header. Alegreya Sans carries everything you read for more than a line, plus metadata and controls.
  • Rough.js outlines mark things you can act on (buttons, fields, dialogs) and a few meaningful annotations. Dividers are a single light ink stroke. Text itself is never drawn.
  • Annotations are data: a circled track is a recorded favourite, “still writing” is a real draft flag, a margin note exists only if it was written.
  • Private stays private. Drafts and private entries never render on public pages; preview is visible only to the author.
  • English and Português (Brasil). The interface switches; writing stays in the language it was written in unless an author translation exists.

04

Layout and spacing

  • Page padding 64px (desktop) · 20px (mobile) · 16px (≤ 370px). Content max width 1312px.
  • Notebook layout for listings, home and studio overview: a 220px margin column for section titles + one writing column, 64px apart.
  • Album and artist journals: two columns 5fr / 7fr with an 88px gap; artwork left, title and writing right. The tracklist sits in the right column.
  • Studio editors: writing column (max 760px) + a 300px margin of settings, 80px apart. On mobile the settings follow the writing.
  • Reading width 62ch. Paragraph spacing 1.25em. Section spacing 96–104px desktop, 72px mobile. Rows 14–16px vertical padding, 44px minimum touch height.

06

Responsive

  • ≤ 720px: one column everywhere; header stacks name over navigation; footer stacks signature over language; tracklist status moves under the title; album grids drop to two columns; artist journals become a list.
  • ≤ 370px: page padding 16px; album title 54px; album grid gap tightens. Verified at 390px and 360px with no horizontal overflow.
  • Touch targets ≥ 44px: navigation links, buttons, language selector, track rows. Exception: star halves are 14 × 28px; give the rating row 44px of height in production, and keep it keyboard-operable as a radio group.
07

Interaction patterns

  • Save: “Unsaved changes” → Save becomes primary → “Saving…” → “Saved just now”. A failed save keeps text locally and offers “Try again”.
  • Publish / Unpublish: always a confirmation that says what will happen. Unpublishing never deletes.
  • Delete: confirmation, then Recently deleted for 30 days with Restore. Removing a catalog record keeps every piece of writing; links become plain text.
  • Preview: opens the public page with a private banner and “Back to editing”.
  • Language selector: footer only; opens upward; arrow keys move through options; Escape closes and returns focus.
  • Motion: underline draws in on hover, outline swaps on hover, chevron changes shape. All transitions stop under prefers-reduced-motion.
08

Implementation notes

  • Generate Rough.js paths once with fixed seeds and ship them as inline SVG; never re-randomise on render.
  • Outlines use preserveAspectRatio=none with vector-effect: non-scaling-stroke so one path fits any button width.
  • The SVG sits behind the label (z-index: -1 inside an isolation: isolate parent); labels stay real, selectable text.
  • Favourite and draft annotations render from data (track.favourite, track.status). Empty tracks are plain text, not disabled buttons.
  • Placeholders in brackets mark the author’s own words. They are never machine-translated.
