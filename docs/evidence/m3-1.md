# M3.1 evidence: the first public reading experience

Issue [#34](https://github.com/RaioViajante/refrain/issues/34), branch `feat/m3-1-public-album-journal`, started from `main` at `74e117b`. This is the record of what was built, what was measured, and what is **not** done. **Everything here is local: nothing is deployed, the public-reads switch is never on in any hosted configuration, the owner's real writing and development database were never read, and no public-release gate is closed.**

Commands are run from the repository root. Counts are from the final head and are repeated in the pull request.

## What exists

| Surface | Route | What it does |
| --- | --- | --- |
| The album journal | `GET /albums/<slug>` | The first anonymous page, in the approved V4.4 "Grace" layout. Read only through `@/modules/publication/public` |
| The status line | `src/proxy.ts` | Decides `404`, `308`, `405`, or `503` for `/albums/<slug>`, the sitemap, and `robots.txt` **before** any page renders |
| The sitemap | `GET /sitemap.xml` | The current address of every publicly visible album journal, and nothing else |
| `robots.txt` | `GET /robots.txt` | Disallows the studio and the authentication endpoints, names the sitemap |
| The not-found view | every other address | One view ("Nothing here") for every reason an address is not served |

There is no list page, artist page, memory page, homepage, language selector, cover image, or provider integration. The header links only to destinations that exist ([Design System § Public album journal](../design-system.md#public-album-journal-m31)).

## Routing and HTTP spike

The task was to prove, on a **production build**, how a real `404` and a real `308` can be sent, before exposing any route. A streamed `200` that contains a redirect is not a `308`. Each experiment below was run against `next build` and `next start` (Next.js 16.4.3, Cache Components on), not the development server, and its result is kept as an executable test (the last column).

| # | Experiment | Result | Kept as |
| --- | --- | --- | --- |
| 1 | A route handler renders the page with `react-dom/server` | The build fails: *You're importing a component that imports react-dom/server*. A handler cannot render the page, so the page has to be a page | (build error) |
| 2 | A page awaits `connection()` at the top, then calls `notFound()` or `permanentRedirect()` | The build fails (*blocking-prerender-dynamic*). With `export const instant = false` it builds, but the response is **`200`** with `x-nextjs-postponed: 1`, and the body carries `NEXT_HTTP_ERROR_FALLBACK;404` or `NEXT_REDIRECT;replace;…;308`. Not a `404`, not a `308` | `public-album-journal.http.test.ts` asserts a hidden address is a real `404` and never contains `NEXT_REDIRECT` |
| 3 | The same behind `<Suspense>` after `connection()` | **`200`** again; a redirect is a streamed meta refresh | same |
| 4 | `proxy.ts` returns its own `Response` with status `404` | A real `404` with the headers chosen. The proxy runs on Node, and bundles `server-only` and the `pg` client | the HTTP matrix |
| 5 | `proxy.ts` returns `new Response(null, { status: 308, headers: { Location: "/x" } })` | **`500`** (*Invalid URL*): the framework's adapter parses `Location` as an absolute URL | M3.1 uses `NextResponse.redirect(new URL(path, request.url), { status: 308 })`, which the framework sends back as a **relative** `Location`. A spoofed `Host`, `X-Forwarded-Host`, and a query string are never reflected (tested with a raw request) |
| 6 | `NextResponse.redirect` | A real `308`, with an added `Refresh: 0;url=…` header and a body that is the destination path. Both are harmless and state-independent | tested: the body is exactly the destination |
| 7 | `proxy.ts` rewrites to an address that no route serves | A real **`404`** with the application's own not-found view, `Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate`, `<meta name="robots" content="noindex">`, and `x-nextjs-cache: HIT` (the view is prerendered at build time, identical for every address) | the matrix compares it byte for byte with an unknown address |
| 8 | A `200` that the proxy passes through to the page | `Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate`. **A prerendered shell exists** (`.next/server/app/albums/[slug].html` and its segment files: the navigation, a "Loading…" line, and the footer, with no journal data). It is deliberate, because a Cache Components page cannot avoid one, and it is what answers a router prefetch. This reads ADR 0006 § 11's "no static shell" more loosely than its letter: what holds is *no journal data and no shared cache*, and the owner should accept or reject that reading | asserted on every `200`, and on every prefetch and segment-prefetch form (below); the build and its cache are scanned for journal text |
| 9 | `sitemap.ts` and `robots.ts` with `connection()` | `Cache-Control: public, max-age=0, must-revalidate`, **not** `no-store`. The convention cannot meet ADR 0006 § 11 | the two are route handlers with explicit `no-store`, and the matrix asserts it |
| 10 | HEAD, POST, and the router's own RSC request (`RSC: 1`) | The proxy decides all of them. An RSC request first gets a `307` to the right `_rsc` value (framework behavior), then the same decision | the matrix, over GET, HEAD, RSC, prefetch, and five other methods |
| 11 | A trailing slash, `/albums/<slug>/` | The framework answers **`308` to the slash-less address before the proxy runs**, with no `no-store`, for every address alike (known, hidden, unknown). It carries no state | tested: the same shape for a public, a draft, and an unknown slug |

**Conclusion.** The required guarantees can be implemented safely, so M3.1 did not stop at the spike. Because a page cannot send a status after it has started, **the proxy decides the status** (the approach the framework documents for a real `404`), and the page resolves the address again itself.

**Residual race, documented.** The proxy decides, then the page reads. If a journal is unpublished in the few milliseconds between the two, the page streams the not-found view with a `200` and `noindex`. It sends no private content (the page re-applies the predicate), and it is the only case in which a hidden address does not get a real `404`. It is a status, not a disclosure.

**Two framework markers remain**, both state-independent and recorded for gate G2: the trailing-slash `308` has no `no-store` (row 11), and the prerendered not-found view carries `x-nextjs-cache: HIT` (row 7); the view is the same bytes for every address and is `no-store`. G2 as worded ("no cache-hit indicator") is therefore **not literally met**: the owner should accept the second marker in writing or reword the gate. Neither is a decision for the implementer.

## The public-reads switch

`REFRAIN_PUBLIC_READS_ENABLED` ([`public-reads.ts`](../../src/modules/publication/public-reads.ts)):

- **Server-only.** Read from the server's environment by server code; no `NEXT_PUBLIC_` name; no request input reaches it (`publicReadsEnabled` is called with no argument in every production file, which a static scan enforces).
- **Off by default, fail closed.** Enabled by exactly `true`. Unit tests cover 23 near-misses (`TRUE`, `True`, `1`, `yes`, `on`, ` true`, `true `, `true\n`, quoted values, and others), the unset and empty cases, and that no other variable counts.
- **Read at request time, never at build.** One production build is served by six servers: switch unset, `true`, `TRUE`, `1`, `yes`, and `True`. Only `true` serves a page; the others answer the unknown-address `404` to every method and every surface.
- **Checked first.** The proxy applies it before the method, the slug, and any query, for the page, the sitemap, and `robots.txt`. The page, the sitemap, and `robots.txt` each check it again.
- **Defense in depth, not a replacement.** The matrix runs with the switch on, and every hidden case is still a `404`: the switch hides and never reveals.

## Predicate integration

Public code reads through one file, [`public.ts`](../../src/modules/publication/public.ts), which exports reads and the switch and imports no command, token, Journals, or Identity code. The read model ([`public-album-journal.ts`](../../src/modules/publication/public-album-journal.ts)) starts every statement from the `publicLanguageVersions` fragment of `predicate.ts`, and reuses the existing `listPublicLanguageVersions`, `getPublicLanguageVersion`, `listPublicTrackReflections`, and `resolvePublicSlug`. No visibility rule is written anywhere else.

Independent checks: a plain-TypeScript oracle written in the test compares the read model with 384 states (deleted or not × the English version draft, private, or published × a Portuguese version absent, draft, private, or published × which one is the original × the reflection flag × a text in each language). For every state the page, the slug resolution, and the sitemap agree with it, and the chosen language, the body's language, the rating, and the reflection are exactly the oracle's. A second test lists the projection's keys at every level and asserts that no `status`, deletion, version, timestamp, slug, or flag appears.

## Anonymous privacy and HTTP matrix

[`public-album-journal.http.test.ts`](../../src/testing/public-album-journal.http.test.ts) (38 tests) and [`public-transitions.http.test.ts`](../../src/testing/public-transitions.http.test.ts) (12 tests) run against the production build and real PostgreSQL, with every request anonymous.

**Hidden addresses** (an unknown one, a draft, a private journal, a deleted journal, the previous and the current address of an unpublished journal, a previous address that was never public, a retired address of a permanently deleted journal, an uppercase slug, an underscore slug, and a slug of 200 characters) each answer **the same status, headers, and body as an unknown address**, for GET, HEAD, an RSC request, a prefetch, with a query string, and with a malformed escape (`400` or `404`, never a stack trace). An unpublished translation is tested as a page: the translation's text never appears, in the page or its RSC payload.

**An eligible journal** answers `200` with `no-store` and no cookie; shows the album, the credit, `1994 · Columbia · 6 tracks`, the opening sentence, the album rating (`[4.5] / 5`), the margin note, the body through the allow-list, the three public reflections, the favourite, `(still writing)`, and a track credit; shows the three tracks without a public reflection as `not written yet`, including the one whose reflection is not public; and has no author control and no studio link. Hostile content is inert: `<img onerror>` is escaped text, a `javascript:` link mark is not a link, an unknown node shows its text only.

**Historical addresses:** the previous address of a public journal is a real `308` with a relative `Location` and `no-store`, for GET, HEAD, and RSC; a spoofed `Host`, a forwarded host, and a query string are never reflected.

**Other surfaces:** the sitemap lists exactly the two served addresses of the run and every listed address is served; `robots.txt` has `no-store`; `405` with `Allow: GET, HEAD` for POST, PUT, PATCH, DELETE, and OPTIONS, identical for every address.

**Failure:** a server with an unreachable database answers a generic `503` with no connection detail; the password in `DATABASE_URL` is in neither the response nor the log.

**Leakage:** every response body and header of both files is kept and scanned, with every server log, for six synthetic private markers (an unflagged reflection, an unpublished translation, a draft, a private journal, a deleted journal, a journal re-addressed and then unpublished) and for table names, a stack trace, and `node_modules`. None appears. The build output and its cache (`.next`) are scanned the same way after the run: no journal text.

## Other request forms (added after the reviews)

[`public-request-forms.http.test.ts`](../../src/testing/public-request-forms.http.test.ts) (64 tests) covers the ways a request can reach a public address that the first matrix did not:

- **Prefetch and transport forms**, for a served address: a router prefetch, a segment prefetch (`/_tree` and the page segment), the raw `.segments/…segment.rsc` files, `.rsc`, `.json`, `/_next/data/<build>/…`, `Accept: application/json` and `text/plain`, `If-None-Match` (`*` and a validator), `If-Modified-Since`, and `Range`. None fails, none is storable (`no-store`, no `public`, `s-maxage`, or positive `max-age`), and none carries private writing. For a **draft**, every one of those forms answers as the same form does for an unknown address.
- **Path and case variants:** `/ALBUMS/…`, `/Albums/…`, `//albums/…`, `/albums//…`, `/albums/./…`, an encoded slash, an encoded dot, a semicolon, and an encoded fragment. A hidden address answers as an unknown one; a served address never fails and never shows private writing.
- **Crawlers and link-preview bots** (`facebookexternalhit`, `Googlebot`, `Twitterbot`, `Slackbot`), which the framework renders on a blocking path rather than the shell: a served page is `200`, `no-store`, with `<title>`, `og:title`, and the opening sentence; a previous address is a `308`; a hidden address is the same `noindex` view as an unknown one.
- **With the switch off**, every public surface (a published journal, a previous address, a draft, the sitemap, `robots.txt`) answers like an unknown address for **every** method (GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS), and for RSC, prefetch, crawler, and `Accept: json` requests: status, headers, and body. The trailing-slash redirect has the same shape for every address, switch on or off.

Two things are masked before two answers are compared, because they describe the request and not a journal: the slug that was asked for (a redirect repeats it in `Location`, `Refresh`, and its body), and the random 22-character key that the framework writes into the Flight data of a page it renders for a crawler. Everything else is compared byte for byte.

What this found: the sitemap and `robots.txt` 404s lacked the security headers that `/albums/*` sent, so they were distinguishable (not a disclosure). `next.config.ts` now sends the same set for `/albums/:path*`, `/sitemap.xml`, and `/robots.txt`: `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, and no framing. The framework already sent `no-store` for each form tested, so this is redundancy for a future upgrade, and no test can tell it from the default.

## Cache and state-transition safety

Each change is made with the real command or a direct write, and the **next** anonymous request is checked; nothing sleeps.

| Change | Next request |
| --- | --- |
| Unpublish (`unpublishLanguageVersion`) | the unknown-address `404`, also over RSC; the sitemap omits it |
| Publish again (`previewPublication`, then `publishLanguageVersion`) | `200` with the text |
| Eight alternations of both | every read matches the state just written |
| Move to Recently deleted | `404`; the sitemap omits it |
| Restore | **still `404`**: a restore never publishes (ADR 0005) |
| Publish after the restore | `200` |
| Change the address | the old address is a `308` to the new; the new is `200` |
| Unpublish a re-addressed journal | both addresses are the unknown `404` at once |
| Publish it again | the redirect returns |
| Return to a previous address | it is current again, and the one it left redirects |
| Publish a Portuguese version, then withdraw the English one | English for an English reader, then the Portuguese version, then `404` |
| Unflag a reflection, flag it, delete its text | the text is absent, present, absent; the track reads `not written yet` |
| Change the album rating, clear it | the new value, then no rating line |
| Edit the opening sentence | the new text, never the old |

Every response class (`200`, its RSC payload, `308`, `404` hidden, `404` unknown, `405`, the sitemap, `robots.txt`) has `no-store`, no `public`, `s-maxage`, or positive `max-age`, and no `Age`, `X-Cache`, `CF-Cache-Status`, or `X-Vercel-Cache`. The only `x-nextjs-cache: HIT` is on the prerendered not-found view. In a browser, going back to a page that was public and has since been unpublished shows the not-found view. **That was tested for a hard navigation (`goto`, then `goBack`) in Chromium only.** An in-application navigation could be served from the client router cache, whose back/forward behavior `staleTimes` does not change; no public link into `/albums/*` exists yet, so it cannot occur today, and it is not a disclosure (the reader had already seen the page).

## Limitations

- Everything is local, over plain `http://127.0.0.1`. No host, CDN, or HTTPS was involved.
- Chromium only.
- The matrix proves the stated cases on the stated build; a static scan is a tripwire, not a proof, and the studio's earlier scans were extended only on purpose (two allow-lists, each reviewed and probed).
- The reader's interface language is fixed to English: the page chooses the version by ADR 0002 D1.2 for an English reader, and there is no way yet to read a Portuguese-first journal as a Portuguese reader.
- The artwork is a fallback. No external image is requested.
- Every request to a well-formed address costs two database queries (the proxy, then the page), and there is no rate limit; the proxy has its own pool.
- The album and artist lists, artist journals, memories, and the homepage do not exist.
