# M3.1 evidence: the first public reading experience

Issue [#34](https://github.com/RaioViajante/refrain/issues/34), branch `feat/m3-1-public-album-journal`, started from `main` at `74e117b`. This is the record of what was built, what was measured, and what is **not** done. **Everything here is local: nothing is deployed, the public-reads switch is never on in any hosted configuration, the owner's real writing and development database were never read, and no public-release gate is closed.**

Commands are run from the repository root. Counts are from the final head and are repeated in the pull request.

## What exists

| Surface | Route | What it does |
| --- | --- | --- |
| The album journal | `GET /albums/<slug>` | The first anonymous page, in the approved V4.4 "Grace" layout. Read only through `@/modules/publication/public` |
| The status line | `src/proxy.ts` | Decides `404`, `308`, `405`, or `503` for `/albums/<slug>`, the sitemap, and `robots.txt` **before** any page renders |
| The sitemap | `GET /sitemap.xml` | The current address of every publicly visible album journal, and nothing else |
| `robots.txt` | `GET /robots.txt` | Disallows the studio and the authentication endpoints, names the sitemap |
| The not-found view | every other address | One view ("Nothing here") for every reason an address is not served |

There is no list page, artist page, memory page, homepage, language selector, cover image, or provider integration. The header links only to destinations that exist ([Design System § Public album journal](../design-system.md#public-album-journal-m31)).

## Routing and HTTP spike

The task was to prove, on a **production build**, how a real `404` and a real `308` can be sent, before exposing any route. A streamed `200` that contains a redirect is not a `308`. Each experiment below was run against `next build` and `next start` (Next.js 16.4.3, Cache Components on), not the development server, and its result is kept as an executable test (the last column).

| # | Experiment | Result | Kept as |
| --- | --- | --- | --- |

| 2 | A page awaits `connection()` at the top, then calls `notFound()` or `permanentRedirect()` | The build fails (*blocking-prerender-dynamic*). With `export const instant = false` it builds, but the response is **`200`** with `x-nextjs-postponed: 1`, and the body carries `NEXT_HTTP_ERROR_FALLBACK;404` or `NEXT_REDIRECT;replace;…;308`. Not a `404`, not a `308` | `public-album-journal.http.test.ts` asserts a hidden address is a real `404` and never contains `NEXT_REDIRECT` |
| 3 | The same behind `<Suspense>` after `connection()` | **`200`** again; a redirect is a streamed meta refresh | same |
| 4 | `proxy.ts` returns its own `Response` with status `404` | A real `404` with the headers chosen. The proxy runs on Node, and bundles `server-only` and the `pg` client | the HTTP matrix |

It is deliberate, because a Cache Components page cannot avoid one, and it is what answers a router prefetch. It is now allowed, on narrow terms, by [ADR 0006 amendment A2](../decisions/0006-publication-decision-and-acknowledgement.md#a2-the-frameworks-cache-marker-and-the-generic-prerendered-shell). | 9 | `sitemap.ts` and `robots.ts` with `connection()` | `Cache-Control: public, max-age=0, must-revalidate`, **not** `no-store`. The convention cannot meet ADR 0006 § 11 | the two are route handlers with explicit `no-store`, and the matrix asserts it |
| 10 | HEAD, POST, and the router's own RSC request (`RSC: 1`) | The proxy decides all of them. An RSC request first gets a `307` to the right `_rsc` value (framework behavior), then the same decision | the matrix, over GET, HEAD, RSC, prefetch, and five other methods |
| 11 | A trailing slash, `/albums/<slug>/` | The framework answered **`308` to the slash-less address before the proxy ran**, with no `no-store`, for every address alike. Its redirect route runs before the proxy, and a framework redirect takes no header from `next.config.ts` (the router returns `resHeaders: null` for it). **Corrected after the owner's final review:** `skipTrailingSlashRedirect` hands the trailing slash to the proxy, which sends the same `308` to the same address (status, `Location`, `Refresh`, and body measured identical to the framework's by a one-off probe of 22 paths × 4 request forms, including the studio, the API, static files, and queries; 14 of those paths are permanent tests), now with `no-store`. Two known differences, both independent of any journal: the framework's proxy adapter removes the router's `_rsc` parameter and a `.rsc` suffix before the proxy sees the address, so `/x/?_rsc=a` now redirects to `/x` (the router then asks again for its `_rsc`), and `/albums/x/.rsc` now redirects to `/albums/x` ([`address-normalization.ts`](../../src/address-normalization.ts)). **Not correctable:** a repeated slash or a backslash (`/albums//x`) is answered by the framework at the top of its router, before any proxy or header rule, with no `Cache-Control` ([below](#the-repeated-slash-308-a-framework-limitation-for-the-owner)) | `public-request-forms.http.test.ts`: every trailing-slash `308` is `no-store` and otherwise unchanged, switch on and off; the repeated-slash shape is fixed by a test that names it as a limitation |

**Conclusion.** The required guarantees can be implemented safely, so M3.1 did not stop at the spike. Because a page cannot send a status after it has started, **the proxy decides the status** (the approach the framework documents for a real `404`), and the page resolves the address again itself.

**Residual race, documented.** The proxy decides, then the page reads. If a journal is unpublished in the few milliseconds between the two, the page streams the not-found view with a `200` and `noindex`. It sends no private content (the page re-applies the predicate), and it is the only case in which a hidden address does not get a real `404`. It is a status, not a disclosure.

**After the owner's final review**, one framework marker is allowed by [ADR 0006 amendment A2](../decisions/0006-publication-decision-and-acknowledgement.md#a2-the-frameworks-cache-marker-and-the-generic-prerendered-shell) under the conditions it names (`x-nextjs-cache: HIT` on three classes of generic, data-free, `no-store` build artifacts), the trailing-slash `308` now carries `no-store`, and **one gap is left open for the owner: the repeated-slash `308`** ([below](#the-repeated-slash-308-a-framework-limitation-for-the-owner)). A2 does not except it.

## The public-reads switch

`REFRAIN_PUBLIC_READS_ENABLED` ([`public-reads.ts`](../../src/modules/publication/public-reads.ts)):

- **Server-only.** Read from the server's environment by server code; no `NEXT_PUBLIC_` name; no request input reaches it (`publicReadsEnabled` is called with no argument in every production file, which a static scan enforces).
- **Off by default, fail closed.** Enabled by exactly `true`. Unit tests cover the near-misses (`TRUE`, `True`, `1`, `yes`, `on`, ` true`, `true `, `true\n`, quoted values, and others), the unset and empty cases, and that no other variable counts. A value with stray whitespace, for example from an `.env` file, therefore leaves reads **off**: it fails closed, and silently.
- **Read at request time, never at build.** One production build is served by nine servers: switch unset, `true`, and seven that are not exactly `true` (`TRUE`, `1`, `yes`, `True`, empty, `true ` with a trailing space, and `false`). Only `true` serves a page; the others answer the unknown-address `404` to every method and every surface.
- **Checked first.** The proxy applies it before the method, the slug, and any query, for the page, the sitemap, and `robots.txt`. The page, the sitemap, and `robots.txt` each check it again.
- **Defense in depth, not a replacement.** The matrix runs with the switch on, and every hidden case is still a `404`: the switch hides and never reveals.

## Predicate integration

Public code reads through one file, [`public.ts`](../../src/modules/publication/public.ts), which exports reads and the switch and imports no command, token, Journals, or Identity code. The read model ([`public-album-journal.ts`](../../src/modules/publication/public-album-journal.ts)) starts every statement from the `publicLanguageVersions` fragment of `predicate.ts`, and reuses the existing `listPublicLanguageVersions`, `getPublicLanguageVersion`, `listPublicTrackReflections`, and `resolvePublicSlug`. No visibility rule is written anywhere else.

Independent checks: a plain-TypeScript oracle written in the test compares the read model with 384 states (deleted or not × the English version draft, private, or published × a Portuguese version absent, draft, private, or published × which one is the original × the reflection flag × a text in each language). For every state the page, the slug resolution, and the sitemap agree with it, and the chosen language, the body's language, the rating, and the reflection are exactly the oracle's. A second test lists the projection's keys at every level and asserts that no `status`, deletion, version, timestamp, slug, or flag appears.

## Anonymous privacy and HTTP matrix

[`public-album-journal.http.test.ts`](../../src/testing/public-album-journal.http.test.ts) (38 tests) and [`public-transitions.http.test.ts`](../../src/testing/public-transitions.http.test.ts) (12 tests) run against the production build and real PostgreSQL, with every request anonymous.

**Hidden addresses** (an unknown one, a draft, a private journal, a deleted journal, the previous and the current address of an unpublished journal, a previous address that was never public, a retired address of a permanently deleted journal, an uppercase slug, an underscore slug, and a slug of 200 characters) each answer **the same status, headers, and body as an unknown address**, for GET, HEAD, an RSC request, a prefetch, with a query string, and with a malformed escape (`400` or `404`, never a stack trace). An unpublished translation is tested as a page: the translation's text never appears, in the page or its RSC payload.

**An eligible journal** answers `200` with `no-store` and no cookie; shows the album, the credit, `1994 · Columbia · 6 tracks`, the opening sentence, the album rating (`[4.5] / 5`), the margin note, the body through the allow-list, the three public reflections, the favourite, `(still writing)`, and a track credit; shows the three tracks without a public reflection as `not written yet`, including the one whose reflection is not public; and has no author control and no studio link. Hostile content is inert: `<img onerror>` is escaped text, a `javascript:` link mark is not a link, an unknown node shows its text only.

**Historical addresses:** the previous address of a public journal is a real `308` with a relative `Location` and `no-store`, for GET, HEAD, and RSC; a spoofed `Host`, a forwarded host, and a query string are never reflected.

**Other surfaces:** the sitemap lists exactly the two served addresses of the run and every listed address is served; `robots.txt` has `no-store`; `405` with `Allow: GET, HEAD` for POST, PUT, PATCH, DELETE, and OPTIONS, identical for every address.

**Failure:** a server with an unreachable database answers a generic `503` with no connection detail; the password in `DATABASE_URL` is in neither the response nor the log.

**Leakage:** every response body and header of both files is kept and scanned, with every server log, for six synthetic private markers (an unflagged reflection, an unpublished translation, a draft, a private journal, a deleted journal, a journal re-addressed and then unpublished) and for table names, a stack trace, and `node_modules`. None appears. The build output and its cache (`.next`) are scanned the same way after the run: no journal text.

## Other request forms (added after the reviews)

[`public-request-forms.http.test.ts`](../../src/testing/public-request-forms.http.test.ts) (64 tests) covers the ways a request can reach a public address that the first matrix did not:

- **Prefetch and transport forms**, for a served address: a router prefetch, a segment prefetch (`/_tree` and the page segment), the raw `.segments/…segment.rsc` files, `.rsc`, `.json`, `/_next/data/<build>/…`, `Accept: application/json` and `text/plain`, `If-None-Match` (`*` and a validator), `If-Modified-Since`, and `Range`. None fails, none is storable (`no-store`, no `public`, `s-maxage`, or positive `max-age`), and none carries private writing. For a **draft**, every one of those forms answers as the same form does for an unknown address.
- **Path and case variants:** `/ALBUMS/…`, `/Albums/…`, `//albums/…`, `/albums//…`, `/albums/./…`, an encoded slash, an encoded dot, a semicolon, and an encoded fragment. A hidden address answers as an unknown one; a served address never fails and never shows private writing.
- **Crawlers and link-preview bots** (`facebookexternalhit`, `Googlebot`, `Twitterbot`, `Slackbot`), which the framework renders on a blocking path rather than the shell: a served page is `200`, `no-store`, with `<title>`, `og:title`, and the opening sentence; a previous address is a `308`; a hidden address is the same `noindex` view as an unknown one.
- **With the switch off**, every public surface (a published journal, a previous address, a draft, the sitemap, `robots.txt`) answers like an unknown address for **every** method (GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS), and for RSC, prefetch, crawler, and `Accept: json` requests: status, headers, and body. The trailing-slash redirect has the same shape for every address, switch on or off.

Two things are masked before two answers are compared, because they describe the request and not a journal: the slug that was asked for (a redirect repeats it in `Location`, `Refresh`, and its body), and the random 22-character key that the framework writes into the Flight data of a page it renders for a crawler. Everything else is compared byte for byte.

What this found: the sitemap and `robots.txt` 404s lacked the security headers that `/albums/*` sent, so they were distinguishable (not a disclosure). `next.config.ts` now sends the same set for `/albums/:path*`, `/sitemap.xml`, and `/robots.txt`: `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, and no framing. The framework already sent `no-store` for each form tested, so this is redundancy for a future upgrade, and no test can tell it from the default.

## Cache and state-transition safety

Each change is made with the real command or a direct write, and the **next** anonymous request is checked; nothing sleeps.

| Change | Next request |
| --- | --- |
| Unpublish (`unpublishLanguageVersion`) | the unknown-address `404`, also over RSC; the sitemap omits it |
| Publish again (`previewPublication`, then `publishLanguageVersion`) | `200` with the text |
| Eight alternations of both | every read matches the state just written |
| Move to Recently deleted | `404`; the sitemap omits it |
| Restore | **still `404`**: a restore never publishes (ADR 0005) |
| Publish after the restore | `200` |
| Change the address | the old address is a `308` to the new; the new is `200` |
| Unpublish a re-addressed journal | both addresses are the unknown `404` at once |
| Publish it again | the redirect returns |
| Return to a previous address | it is current again, and the one it left redirects |
| Publish a Portuguese version, then withdraw the English one | English for an English reader, then the Portuguese version, then `404` |
| Unflag a reflection, flag it, delete its text | the text is absent, present, absent; the track reads `not written yet` |
| Change the album rating, clear it | the new value, then no rating line |
| Edit the opening sentence | the new text, never the old |

Every response class (`200`, its RSC payload, `308`, `404` hidden, `404` unknown, `405`, the sitemap, `robots.txt`) has `no-store`, no `public`, `s-maxage`, or positive `max-age`, and no `Age`, `X-Cache`, `CF-Cache-Status`, or `X-Vercel-Cache`. `x-nextjs-cache: HIT` appears only on prerendered build artifacts, in three classes ([G2 and the cache-hit marker](#g2-and-the-cache-hit-marker)). In a browser, going back to a page that was public and has since been unpublished shows the not-found view. **That was tested for a hard navigation (`goto`, then `goBack`) in Chromium only.** An in-application navigation could be served from the client router cache, whose back/forward behavior `staleTimes` does not change; no public link into `/albums/*` exists yet, so it cannot occur today, and it is not a disclosure (the reader had already seen the page).

## Owner review of PR #35: the cache-hit marker, the shell, and the guards

The owner's review of the first handoff asked for a measured answer on three points, each with the accepted ADR's exact wording. The second review was answered with proposals only, and no ADR was changed. **In the final review the owner approved a narrowed design, now [ADR 0006 amendment A2](../decisions/0006-publication-decision-and-acknowledgement.md#a2-the-frameworks-cache-marker-and-the-generic-prerendered-shell).** The original text is unchanged, with pointers. The measurements below are what A2 rests on.

### G2 and the cache-hit marker

**The accepted wording** ([ADR 0006 § 14, G2](../decisions/0006-publication-decision-and-acknowledgement.md#14-public-page-release-gates)): *"`Cache-Control: no-store` is present on every response class, and no response carries a cache-hit indicator."* G2 is one of the gates that cannot be waived (§ 14, waivers).

**Where `x-nextjs-cache: HIT` appears, on the production build** ([`public-cache-indicator.http.test.ts`](../../src/testing/public-cache-indicator.http.test.ts), 11 tests):

| Response | Carries the marker | What its bytes are |
| --- | --- | --- |
| The not-found view (`404`), for every address that is not served and for every public document with the switch off | Yes | exactly `.next/server/app/_not-found.html`, written at build time |
| A segment prefetch of a **served** address (`Next-Router-Segment-Prefetch: /_tree`, and the page segment) | Yes | exactly the build's `albums/[slug].segments/*.rsc` files: the data-free shell |
| A bare router prefetch (`RSC` and `Next-Router-Prefetch`, no segment header) of a served address | Yes | an empty `404` body |
| A served page, its full RSC payload, the page rendered for a crawler, a `308`, the sitemap, `robots.txt`, `405` | **No** | rendered for this request from the database |
| `/artwork/refrain-404.webp` | No | a static file, byte for byte the approved production copy (the PNG at this row's first measurement) |

The first version of this evidence said the marker was on the not-found view only. The second row is a finding of this review: **a response for a served address can carry the marker**. It holds no entry data, as the test proves: every marked response is either empty or *exactly* a file the build wrote before any journal existed.

**The five questions.**

1. *Does the marker vary between unknown and non-visible resources?* No. For an unknown address and for each of draft, private, deleted-never-public, unpublished after being public, deleted after being public, restored (which stays private), the retired address of an unpublished entry, and its current address, status, every header (including the marker) and the body are identical, over GET, HEAD, RSC, router prefetch, and a crawler user agent (status, the marker, and `Cache-Control` for every hidden kind in [`public-cache-indicator.http.test.ts`](../../src/testing/public-cache-indicator.http.test.ts); the **full** snapshot, every header and the body, for RSC and prefetch in [`public-album-journal.http.test.ts`](../../src/testing/public-album-journal.http.test.ts), and for the segment forms (`_full`, `_head`, `_tree`, a segment path that names the address itself), a forged session cookie, and conditional and range headers in the new "every transport form" tests). A fresh process, whose first request is a hidden address, answers the same. A hostile `Host` and `X-Forwarded-Host` are reflected into no response of the rewrite path (raw-request test).
2. *Can request history influence it?* No. 75 mixed requests to a hidden, an unknown, and a served address change nothing; the marker is a property of the build artifact, which is never regenerated (no revalidation), and the first request of a fresh process already carries it.
3. *Can headers, time, status, or body reveal the existence or publication history of a private journal?* Status, headers, and body: no (above). Time: a hidden address and an unknown one run the same code (one slug query, then the same rewrite to the same prerendered view). Measured on this machine with 80 interleaved pairs after a warm-up, three runs: medians 1.46 against 1.43 ms, 1.50 against 1.48 ms, and 1.38 against 1.38 ms. The test asserts less than 15 ms. That is a tripwire for a **gross** difference (a slow branch, an external call), **not** for an extra query, which costs far less than the margin, and not a constant-time proof; the medians above were observed once, locally, and are not an assertion. The one difference is between a *served* address and the rest, which is the public status itself.
4. *Can a cache-hit indicator accompany entry-specific private content?* No on the production build: it is on bytes that are identical to a build file for every address, and it is absent from every response that is rendered from the database. Nothing on this build is cached or revalidated.
5. *Does the implementation meet the privacy guarantee even though not the literal wording?* **Yes for the guarantee, no for the wording.** The guarantee behind G2 is that no stale or cached entry state is served and that nothing reveals state; both hold and are tested. The words "no response carries a cache-hit indicator" are not met, because the framework stamps its own prerendered artifacts. No way to remove that header from the application was found (it is added after the proxy and `next.config.ts` run); that was reasoned from the framework's behavior, not tested. The trailing-slash `308` lacked `no-store` at the time (row 11); since the final review the proxy sends it with `no-store`.

**Amendment A2, approved by the owner and applied.** The owner approved a narrowly scoped clarification, now [ADR 0006 amendment A2](../decisions/0006-publication-decision-and-acknowledgement.md#a2-the-frameworks-cache-marker-and-the-generic-prerendered-shell). The original text is unchanged, and pointers mark the places it touches. It allows the framework's `x-nextjs-cache: HIT` and no other indicator, only on a response that is generic and entry-independent, empty or byte-identical to a verified data-free build file, free of entry-specific metadata, `no-store`, and indistinguishable across unknown and every non-visible state. G2's first sentence, `no-store` on every response class, is **unchanged**. G2 stays mandatory and non-waivable. An earlier draft here would have made `no-store` conditional; the reviews rejected that, and A2 does not do it.

### The repeated-slash `308`: a framework limitation, for the owner

Next.js 16.4.3 answers a path containing `//` or a backslash with a `308` to the collapsed path, at the top of `resolve-routes` (`server/lib/router-utils/resolve-routes.js`, before the header rules, the redirects, and the proxy), with an empty header set. No configuration or application code can add `Cache-Control` to it. A custom server could, but would be an extra service outside the architecture. Measured, it is the same for every address (served, draft, unknown), switch on or off, and its body is the destination path. It is a cacheable `308` that never depends on a journal: a cached one would keep sending `/albums//x` to `/albums/x`, which is where it always goes. **It does not meet G2's first sentence, and A2 does not except it.** A test fixes its exact shape (`public-request-forms.http.test.ts`), so a framework change is noticed. G2 cannot be waived (§ 14), so the gap is not something to accept in writing. It closes only by a further ADR amendment that the owner decides, or by a hosted CDN or proxy rule, verified under G2 on the hosted configuration, that adds `no-store` or normalizes the path first.

### What the build prerenders (ADR 0006 § 11)

**The accepted wording**, in the ADR's own order. § 11, first bullet:

> There is no static generation or incremental regeneration of journal data, no `use cache` of it, and no `generateStaticParams` for journal routes.

> Nothing journal-related is rendered at build time; the build needs no database, which CI already proves.

§ 11, second bullet:

> a streamed redirect is not a `308` (INV-5), a shell is not a per-request `404`, and a prerendered shell is not `no-store` per request. The address must be resolved, and the status and headers chosen, before any response byte is sent, for example in a route handler or before any `Suspense` boundary.

and the spike's requirement, in the same bullet:

> proves, on the production build, real `308` and `404` statuses, `no-store` on `200`, `308`, and `404`, and no static shell or journal data in the build output.

**What Next.js prerenders** ([`public-build-output.http.test.ts`](../../src/testing/public-build-output.http.test.ts), 6 tests, which read the build's own files, not the source. That the build reached no database is **not asserted by these tests**: CI builds without `DATABASE_URL` ([`ci.yml`](../../.github/workflows/ci.yml), the build step), and the tests read whatever `.next` exists. Journal text is checked against a list of the fixture's words, not by a general rule):

- In `prerender-manifest.json`: no route under `/albums/` except the dynamic `/albums/[slug]`, a `PARTIALLY_STATIC` **fallback** keyed on the parameter `slug` itself (no value of it). No `generateStaticParams`, so no concrete address.
- `.next/server/app/albums/` holds exactly `[slug].html`, `[slug].meta`, and `[slug].segments/` (`_tree`, `_full`, and the page segment).
- **The shell's whole visible text** is *"Skip to content Home Albums Loading… some songs take you back."* Its only links are `#main` and `/`. It has no `<title>`, no description, no Open Graph or Twitter tag, no canonical link, and no data island. Its single behavior is `aria-busy="true"` on a loading line.
- The segment and postponed-state files name the route by its pattern (`[slug]`, `$d$slug`) and never by an address, and contain none of the fixture's words.
- `_not-found.html`: one view, the same for every address: *"Not found · refrain"*, the navigation, "Nothing here", "This page is not available.", the link back, and the footer, plus the approved drawing as an `<img>` of its production copy (`/artwork/refrain-404.webp`, with its width and height). It has `noindex`, and holds no path, slug, or entry.
- Nothing in either contains `[Test]`, `Grace`, `Buckley`, or any marker.

**Is it entry-dependent, journal content, private metadata, or visibility state?** No to each, by inspection of the files. It is the same bytes whatever the database holds, and CI's build, which has no `DATABASE_URL`, produces them.

**Why it cannot be removed.** The spike (rows 2 and 3) shows that under Cache Components a page that awaits request data must sit behind `Suspense`, or the build fails (*blocking-prerender-dynamic*); the `Suspense` fallback *is* the shell. Not having one would mean leaving Cache Components, which is an architecture decision, not a local fix.

**Compatibility.** Not literally met in two places, and the owner decides whether the shell reading is accepted: (1) *"Nothing journal-related is rendered at build time"*: a fallback shell for the route `/albums/[slug]` **is** rendered at build time. It is generic (no journal, no address, no state), but it belongs to a journal route, so this sentence is met only if the owner accepts that reading. (2) The spike's *"no static shell"*: a shell exists. The first sentence (no generation of journal data) and the second bullet (the shell decides no status, and is sent with `no-store`, tested on every request form) are met. A passing test does not resolve a conflict in the documentation.

**Two further facts for the owner.** The shell's responses carry `x-nextjs-stale-time: 300`, which lets the client router reuse a prefetched shell for five minutes; it is harmless while the shell is data-free, but when a later milestone adds links to journals, a prefetched not-found for an address that has just been published could be reused for that long, so **M3.2 must re-measure it**. And the not-found artifacts (`_not-found.html`, `.rsc`, `.segments/`) also come from the build and answer every journal address that is not served.

**Clarification A2, approved by the owner and applied.** The shell is allowed as the framework's generic fallback with universal site elements only (navigation, skip link, loading indicator, footer), and the shared not-found view on the same terms. It may hold no journal text, entry-specific metadata, concrete address, language-specific private content, visibility or deletion state, or anything that establishes that a private journal exists. No journal data is ever prerendered or cached ([A2](../decisions/0006-publication-decision-and-acknowledgement.md#a2-the-frameworks-cache-marker-and-the-generic-prerendered-shell)). **The exact class:** the `PARTIALLY_STATIC` fallback of `/albums/[slug]` (`.next/server/app/albums/[slug].html`, `.meta`, `.segments/{_tree,_full,…/__PAGE__}.segment.rsc`), and `_not-found.html`, `.rsc`, and `.segments/`. **The tests that hold the boundary:** `public-build-output.http.test.ts` (the files and their contents) and `public-cache-indicator.http.test.ts` (the responses that serve them, and that no file named for an address appears afterwards).

### Skip link, the switch scan, the guard tests, and the 404 drawing

- **Skip link.** "Skip to content" is the first tab stop of the public pages (the journal and the not-found view). - **The switch scan** ([`public-surface.test.ts`](../../src/app/public-surface.test.ts)) is now structural: a read must be preceded by a top-level `if (!publicReadsEnabled()) <exit>` statement (alone or an operand of `||`, no `else`, a `return`, `throw`, `notFound()`, or `redirect()`), which must not itself hold a read; a bare reference to a read, an aliased or namespace import, a read at module level or in a parameter default, a read by element access, a local stand-in for the switch or for `notFound`, and a concise arrow body are rejected. 23 probes show each rejected shape (a guard after the read, ignored, conditional, nested, inside a `try` with the read, or in a nested function). Studio-only data: the read model's keys are fixed at every level (the earlier integration test), and a new HTTP test finds none of the entry, album, artist, or track ids in the page or its payload.
- **The 404 drawing.** `reference/refrain-404.png` exists (1536×1024, 8-bit RGBA, not interlaced, 2,824,585 bytes, SHA-256 `7705f803…c4956`). **Its transparency is genuine**: 48.9% of the pixels have alpha 0, the four corners are alpha 0, and the drawing is solid (maximum alpha 254). ## Limitations

- Everything is local, over plain `http://127.0.0.1`. No host, CDN, or HTTPS was involved.
- Chromium only.
- While a page streams, a second `<main id="main">` (the loading fallback and the hidden template) exists until React swaps them; a very fast Tab and Enter could reach the fallback. No duplicate remains after the swap.
- The skip link needs `:has()`; without it the link sits over the navigation while focused.
- The matrix proves the stated cases on the stated build; a static scan is a tripwire, not a proof, and the studio's earlier scans were extended only on purpose (two allow-lists, each reviewed and probed).
- The reader's interface language is fixed to English: the page chooses the version by ADR 0002 D1.2 for an English reader, and there is no way yet to read a Portuguese-first journal as a Portuguese reader.
- The artwork is a fallback. No external image is requested.
- Every request to a well-formed address costs two database queries (the proxy, then the page), and there is no rate limit; the proxy has its own pool.
- The album and artist lists, artist journals, memories, and the homepage do not exist.
