# Evidence: M3.6, the Memories Studio

## Scope

The private Writing Studio for memories, on the existing `memory` entry kind (issue #48, pull request #49), authorized by the owner on 2026-11-03. **No memory is public**, nothing is deployed, and no release gate is closed. M3.7 builds the public memory page and memory publication.

Owner decisions applied: the existing `memory` kind (no `song_journal`); a memory is independent writing linked to zero or more catalog recordings in order (`memory_music.track_id`), with no grouping of recordings into a "song"; no ratings or favourites; track reflections stay separate; catalog recordings only (no MusicBrainz track search, no artwork); English-only memory writing; `remembered_when` stays one value for the entry. No migration, no dependency, no ADR change.

## Baseline

`main` at `609f05234bc2f7497a7bd5e5d5fb89d856051ea7`, clean, on 2026-11-03. The schema already held `memories (entry_id, remembered_when)` and `memory_music (memory_id, position, track_id | album_id)` with `UNIQUE (memory_id, track_id)`, `CHECK (num_nonnulls(track_id, album_id) = 1)`, foreign keys to the catalog `ON DELETE RESTRICT`, and `UNIQUE (memory_id, position) DEFERRABLE INITIALLY DEFERRED` (migration `0001`). No command wrote either table; the Publication engine's disclosure already read them (ADR 0006 § 1, "Memory details").

## Memory commands and data behaviour

In [`src/modules/journals/memories.ts`](../../src/modules/journals/memories.ts), each one transaction, each taking the `AuthorizedAuthor`, each validating with Zod ([`input.ts`](../../src/modules/journals/input.ts)):

| Command | Behaviour |
| --- | --- |
| `createMemory` | The entry (`kind = 'memory'`), its original `en` version as a `draft` with the title and the writing (stored as the accepted document format), the `memories` row with its "when", the ordered links (positions 1..n), and a reserved slug from the title (fallback `memory`). Refuses a blank title, another language, a duplicated, unknown (`track_not_found`), or archived (`track_archived`) recording. Unknown keys (`status`, `ratingHalfSteps`, `kind`, `version`) are dropped |
| `saveMemory` | A patch of the title, "when", writing, and the whole ordered recording list, under the entry lock joined to `memories`, after the `entries.version` check, and bumping it. Every check precedes the first write. A recording left out loses only its link; a kept one keeps its row and takes its new place (the deferred constraint allows swaps); a new one is checked like a create. An existing link to a recording archived since is kept and can move. Refused, writing nothing: `entry_deleted`, `version_conflict`, `memory_published`, `unsupported_content` (writing the plain editor cannot reproduce, or a memory that has an album link, which the studio cannot show), and the input and recording refusals |
| `setMemoryPrivacy` | `draft` or `private` only, through `unpublishLanguageVersion`, if the version still has the status the screen showed (`status_changed`) |
| `deleteMemory`, `restoreMemory` | `deleted_at`, and `restoreDeletedEntry` (a published version returns as private; writing, links, history, slugs, and `entries.version` untouched; a second restore is `entry_not_deleted`) |

A recording deleted from the catalog between the check and the insert is refused by `memory_music_track_fk` and reported as `track_not_found`, never as a database error.

Queries ([`memory-queries.ts`](../../src/modules/journals/memory-queries.ts)): the list, Recently deleted, one memory with its recordings (credited artists, albums, length, archived), the memories of a recording, and a statistics aggregate. The academic queries AC-04 and AC-05 are unchanged. The Catalog adds `listRecordingChoices` (recordings that are not archived, with the same facts).

## Studio

`/studio/memories` (list, empty state, totals), `/studio/memories/new` (with `?track=` from a track's page, accepted only for a recording that exists and is not archived), `/studio/memories/<id>` (the editor, or a read-only view with Restore… while in Recently deleted). The Desk gains Write a memory and a memories section; Recently deleted lists memories under their own heading; a track's page lists its memories and offers Write a memory about this song. The editor: title, When, the memory with its word count, The music (Move up, Move down, Remove; the in-catalog picker), Artists, from the music, Written in, Visibility (Draft and Private), Delete…. Save or Cmd/Ctrl+S; leaving with unsaved changes asks first; Delete waits until changes are saved.

## Privacy and publication restrictions

- No memory preview, publish wrapper, or Server Action exists. The album-journal publish wrappers check the kind and answer `not_found` for a memory. The Publication engine stays generic, as ADR 0006 § 2 specifies; presentation cannot reach it (`no-publishing.test.ts`).
- A memory with a published version cannot be saved (`memory_published`, under the lock, before any write); making it private is allowed.
- No public route serves a memory: `/memories/<slug>`, `/memories`, and `/albums/<memory slug>` answer `404`. A memory's slug is reserved but never marked as published.
- `createMemory` and `saveMemory` join the ADR 0006 § 9 writer allowlist; the scans still fail on any other writer of `memories` or `memory_music`. They were added on this branch without the owner's approval and are approved since 2026-11-03 ([below](#owner-technical-approval)).

## Owner technical approval

On 2026-11-03, after the technical audit of the reviewed head `1f22f6acf13190da205108b000624e2fa1e98454`, the owner approved M3.6 technically, and explicitly approved `src/modules/journals/memories.ts#createMemory` and `src/modules/journals/memories.ts#saveMemory` on the writer allowlist under ADR 0006 § 9's existing review requirement. ## Remaining limitations

- The album journal's editor shares the sticky bar that can cover a focused field on a phone after a long refusal; only the memory editor's is fixed here (issue #50).
- Not tested with real connections: a save racing a privacy change or a restore (both lock the entry first, as the tested pairs do), and that `entries.updated_at` moves on a list-only save (Drizzle's `$onUpdateFn` sets it).
- A recording archived between a save's check and its insert can be linked (ADR 0006 L3, as for reflections).
- A memory with an album link (only a write outside the studio can make one) shows it, and its recording list cannot be saved.
- English-only memory writing; `remembered_when` is one value for the entry.
- Behaviour over real HTTPS is not verified (as for the whole studio, issue #11).
