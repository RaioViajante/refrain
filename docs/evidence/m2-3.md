# Evidence for M2.3: studio publication and confirmation workflows

**What this is.** A record of what M2.3 built, how it was checked, and what was not. Everything is synthetic (`[Test] …`) and ran against the **disposable test database**, never the development database. It describes the branch `feat/m2-3-studio-publication` (issue #31). It is not a claim that anything is public: no public route exists, `REFRAIN_PUBLIC_READS_ENABLED` is not built, and gates G1 to G8 of [ADR 0006](../decisions/0006-publication-decision-and-acknowledgement.md#14-public-page-release-gates) stay open. The catalog-wording gap (C11) stays explicit.

## Behavior in one place

- **Preview.** *Publish…* on a version asks the server for a review: the opening sentence, the reflection, the address, the album rating, every track reflection that will be public with its track and language, a count, and what stays private (written reflections not set to show, by track title only). It writes nothing and changes no visibility. The review is `no-store`, goes only to the authorized request, and carries the confirmation token to the dialog only.
- **Publish.** The dialog's confirm control ("Publish the English version") sends the token the preview returned, in a separate request. Focus starts on the dialog's title, not on the confirm control. The studio reports success only after the server committed. It says what that means: the version is marked published in the records and **no web page exists yet**.
- **Refusals.** A missing, malformed, forged, wrong-session, wrong-purpose, wrong-language, expired, or stale token, a stale editor, a deleted journal, and an unpublishable or addressless version are refused with a fixed code and nothing written. The dialog drops the token, says so, takes focus to that notice, and waits for the author to ask for a new review.
- **Closing a review changes nothing** (owner decision on PR #32). The review has no control that saves: Cancel, Escape, and opening it again leave every flag, version, status, and row as it was, and the token still works. To change which reflections are shown the review links to the track editor, where the ordinary save applies; a new review then lists the set as it stands. This replaces the design system's per-row unchecking inside the dialog, which [ADR 0006 § 2](../decisions/0006-publication-decision-and-acknowledgement.md#2-the-disclosure) describes as an immediate ordinary save. The ADR is not edited; it should be amended if the owner keeps this behavior.
- **Unpublish.** Asks first, moves one language version to *private* or *draft*, and keeps the writing, `first_published_at`, the address, and every other language version.
- **Stale tabs.** Draft, Private, and Unpublish carry the status the screen showed (`expectedStatus`), checked under the entry lock; a stale one is refused as `status_changed` with a message, nothing changes, and the page refreshes to the real state. Before, a tab that still showed *Private* could unpublish a version that another tab had published.
- **Confirmed edit.** Saving a journal that has a published version first asks the server what would change, and shows it before and after ("Published now", "Published after saving"). "Save and update published writing" sends the `change_public` token, only from that dialog. A longer text, a **shorter** one, and a cleared field all count. A save that changes nothing a reader sees, and a removal, save with no dialog. Cancelling keeps every word in the editor; a conflict keeps it too. Cmd+S and double submission do not start a second save.
- **Text the plain view cannot show** cannot be confirmed from the studio (the author could not have read it).
- **Wording.** The studio says "published writing" and says that no web page exists yet. Left as the design system names them, for the owner to decide: the track setting "Show on the public page" and its hints (M2.2, V4.4 text).
- **Restore and Recently deleted copy** now says what the built flow does: restoring publishes nothing, and publishing again shows the full review first, including any track reflections that were set to show.
- **Revalidation.** One module refreshes the private studio. The list of public paths is empty because no public page exists and nothing public is cached ([ADR 0006 § 11](../decisions/0006-publication-decision-and-acknowledgement.md#11-public-reads-and-caches)). The ADR describes no cache invalidation to build, so this is a seam for M3.1, **not** a claim that public invalidation is done.

## CI stability: `src/design/strokes.test.ts`

CI run 41380685474 failed once on that test ("Test timed out in 5000ms") and passed on a re-run of the failed job. **A passing re-run is not evidence of a fix**, and none is claimed. What was found: `strokes()` redraws every Rough.js stroke on each call (about 200 ms here), and "stay inside their box" called it once per size, eight times, about 1.5 s on this machine, with thousands of `expect` calls, while 21 test files ran in parallel on a slower runner. That is a plausible cause of crossing 5 s; the timeout itself was not reproduced locally. The test now generates the strokes once (about 190 ms, an eight-fold reduction) and **every assertion is unchanged**; no timeout was raised, and no stroke behavior changed. If it fails again in CI, the next step is a separate maintenance issue, not a longer timeout.

## Independent reviews

The first round, below, describes the dialog as it was then: its in-dialog removal and its notice about removal were **superseded** by the owner's decision (see "Closing a review changes nothing").

Three read-only reviews in fresh contexts (security and command boundary with `refrain-security-review`; publication workflow and concurrency; visual and accessibility against V4.4). No Critical or High finding. Resolved:

- **Security, Medium.** The mint-and-consume scan did not know the client's action names. A dialog scan now reads each dialog's handlers by name (previews only in `fetchPreview`, the publish only in `confirm`, a removal never sends a token, nothing from a catch handler, an effect, or a timer), with probes. The studio scan also catches element access by name and dynamic imports. Low: a failing refresh no longer reports a committed publication as "nothing was changed"; stale comments fixed.
- **Workflow, Medium.** The "every command moves the stamp" test now checks the timestamp each command owns (it compared the status too, so two mutants survived), a committed replay after publish and unpublish is refused, and the HTTP suite covers the other purpose's token and previews of deleted and unknown journals. Copy that overstated a public page was fixed in the track-by-track line and the unpublish text. A lost response is no longer reported as "nothing was changed". The "before" side of a new field no longer says "cleared". Removing a reflection says it also stops it showing in other languages.
- **Visual and accessibility, Medium.** The intro no longer says nothing is changed beside an immediate removal, and a notice confirms the removal; before and after labels are distinct; the no-web-page caveat is at the top of the change dialog; a notice takes focus so a refusal is read first (no `aria-busy` over a live region); the reading area keeps a minimum height and the dialog scrolls on a very short screen.

Accepted, not changed (see the pull request): the Draft and Private buttons of a tab that is stale can still unpublish a version that was published elsewhere (it only reduces exposure); a token supplied with no change is checked for authenticity before the lock rather than ignored unread (the UI never sends one); the dialog titles use the design system's "public page" wording while the body says no page exists yet; the Visibility panel is in the journal page's Manage column because the editor has no version tabs.

## Follow-up after the owner's review of PR #32

Closing a review changes nothing, wording says published writing, a stale status change is refused, and the strokes test generates once (all above). Re-run on the new head: unit, integration, HTTP, and the browser suite (117 tests, desktop and 390 px, axe); screenshots regenerated. A focused independent review of the security-relevant part (the expected-status check, the removal of the dialog's save, the test helper import) found no Critical, High, or Medium finding. Its two Low findings were acted on: the dialog scan now allows each dialog exactly its own action imports and flags an action that is aliased or passed on, and a real two-connection test races a stale Draft against a publication holding the entry lock.

## Not verified

- Behavior over real HTTPS, a screen reader, other browsers, a real phone, forced colors and reduced motion in the dialogs, and every gate G1 to G8.
- That a reviewer's static read found no other path: the scans are tripwires, not proofs. Out-of-process writers (a script, `psql`, a migration, a backup restore) remain unconstrained until gates G3 and G4 close.
- Expiry in the browser (the dialog says the review ran out; the 15 minutes themselves are tested at the command boundary), and a session that ends while a dialog is open.
- Brazilian Portuguese strings (English only is the documented interim).
