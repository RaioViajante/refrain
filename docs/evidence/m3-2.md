## Baseline and the schema decision

The schema of M1.2 already holds every identity, each `UNIQUE` and `NULL` for manual records: `albums.mb_release_group_id` (the album is the release group, ADR 0002), `album_editions.mb_release_id` (the reference edition is one release), `tracks.mb_recording_id`, and `artists.mb_artist_id`. Artwork has `albums.cover_url` and `albums.cover_source`, with `CHECK (cover_url is null or cover_source is not null)`. No application code wrote either cover column before M3.2.

**Decision: no migration.** Provenance is exact in the existing columns, because the application writes one form only, `https://coverartarchive.org/release/<release MBID>/<image id>`, which names the release and the image the author chose (never the archive's movable "front" alias). Safety does not rest on what the column holds: every reader parses that form strictly and rebuilds the image addresses from the two parts, so anything else in the column (written by `psql`, a restore, or a bug) is shown as the fallback and never loaded, and the CSP refuses any other host in the browser. A database `CHECK` on the form would be defense in depth; it is listed under [Deferred](#deferred) rather than added without the owner's approval.

## Identity and selection

- **The author chooses every record.** A search result is never added: an album leads to its release group's editions, an edition to a review, and only **Add to catalog** on the review writes. An artist leads to its own review. Nothing is guessed from a title.
- **Release group and release stay distinct.** The album is the release group (its title and first-release year); the reference edition is the chosen release (its label, full release date, country, and tracklist, disc by disc). A partial date is not stored as a full one; the review says so.
- **Credits.** The release's artist credit in order, each artist once, with the printed name kept as `credited_as` when it differs from the artist's own name; each new recording gets its own credited artists. MusicBrainz join phrases ("feat.", "&") are shown in the review but not stored (the catalog has no column for them), and the public page joins names with commas as before.
- **Ambiguous and incomplete results.** Results with the same title stay separate rows with their credit, year, types, and disambiguation; missing fields show as "not given"; an edition with no tracks, too many, a recording listed twice, or an over-long text is refused with the reason and can still be entered by hand or linked.
- **Existing records.** An artist or recording already in the catalog (by MBID) is reused exactly as it is; an archived one is refused. An album or edition already in the catalog is refused (`duplicate`). An album or artist with the same title or name and no MBID is offered a **link** instead, after a confirmation; linking fills only empty identifiers and never replaces one (`already_linked`).
- **Exactness.** The review carries a SHA-256 of the plan. On approval the server fetches the release again (before any transaction), rebuilds the plan, and writes only if the fingerprint matches; otherwise `stale`, nothing written.

## Artwork behavior

- **Choice.** Only images the archive lists as front covers are offered; none is selected by default. On the album page, covers come from the reference edition's release, or the release group's listing when only that is linked. A chosen image must belong to the album's own release or release group.
- **No silent replacement.** Every change sends the artwork the author was looking at, compared under the album's row lock (`stale` otherwise). Removing asks first.
- **Public pages (G8).** While any journal about the album is publicly visible (decided by the predicate; a published translation is enough), artwork cannot be set, replaced, or removed, and the artwork page says why. The command locks every journal entry of the album `FOR SHARE` before deciding, so a concurrent publish (`FOR UPDATE`) waits for it; a real-connection test shows the lock is held. Importing creates new albums, which no journal shows yet; linking changes nothing a page shows. This does **not** close C11: catalog wording still changes public pages without confirmation, as before.
- **Fallback.** The frame is a fixed 1:1 box with the fallback inside it; the image is absolutely positioned over it with `object-fit: cover`, so loading or failing moves nothing. A failed image draws nothing (`alt=""`; the frame carries the name), and the fallback remains.
- **Public page.** The read model selects `cover_url` and `cover_source` through the same predicate-bound statement as the album's other facts, and returns only `{ src, srcSet }`. A draft, private, or deleted journal is still the unknown-address `404`, with no cover in it.

## Caching and limits

| Layer | What | Bound |
| --- | --- | --- |
| MusicBrainz responses | Validated searches (10 min) and lookups (1 h), in the server process's memory | 200 entries, oldest dropped; failures never cached; nothing of the author's in it |
| Cover listings | Validated listings (1 h), "no artwork" (10 min) | 200 entries |
| Images | Not cached by Refrain; the browser's cache and the archive's | No image bytes are stored in the database or on disk |

The cache is per process and in memory: a restart empties it. Nothing public is cached (ADR 0006 § 11 unchanged); the image requests go from the reader's browser to the archive.

## Security and privacy boundaries

The rules are in [Security § External providers](../security.md#external-providers), and the controls with their tests in [Security § Implemented (M3.2)](../security.md#implemented-m32-on-its-branch-until-merged). In short: provider calls only from the server, only after authorization (an anonymous request causes none, read from the mock's log); requests carry an MBID or the typed words, nothing else; no credentials, no referrer; base URLs fixed unless pointed at a loopback mock; HTTPS-only allow-listed redirects; response size limits and Zod validation; Lucene syntax escaped; covers rendered only from their one stored form; `img-src` limited to the archive; nothing written without an approved review.

What a reader's browser reveals: loading a cover tells the Cover Art Archive and the Internet Archive the reader's address and which cover is shown, as any third-party image does; it never sends the page's address (`no-referrer`). Proxying images through Refrain would hide that, at the cost of a public image endpoint and a cache; it is deferred.

## Rights and attribution

- **Data.** MusicBrainz core data (titles, credits, tracklists) is CC0. Refrain credits it anyway in the studio ("Data from MusicBrainz").
- **Covers.** Cover images are copyrighted by their owners. The Cover Art Archive grants no general licence over them and asks users to respect the rights of artists and labels. That the archive's API serves an image grants no reuse rights, and Refrain claims none.
- **Approved scope.** The owner approved the integration for local development (final review of pull request #37). Locally, a cover is shown only because the author chose it, for the album a journal is about, at thumbnail size, unaltered, and credited "Cover: Cover Art Archive" in the studio and on the public page.
- **Before a hosted page shows covers.** The rights review is a hosted-release requirement: [Security § Deployment gate](../security.md#deployment-gate), item 6. The fallback frame remains for every album without an approved cover.
- **In the repository.** No cover image, real or derived, is committed. Tests use generated flat-color SVGs.
