# Evidence for M2.2: track-by-track writing and confirmed changes

**What this is.** A record of what M2.2 built, how it was checked, and what was not. Everything is synthetic (`[Test] …`) and ran against the **disposable test database**, never the development database. It describes the branch `feat/m2-2-track-by-track-writing` (pull request #30, issue #29). It is not a claim that anything is public: nothing publishes, and gates G1 to G8 of [ADR 0006](../decisions/0006-publication-decision-and-acknowledgement.md#14-public-page-release-gates) stay open.

## Behavior in one place

- **Reflections.** Text per language (a blank, or invisible-only, text removes that language's row, so a row means text), the favourite mark (belongs to the track **in this journal**, no limit), "still writing" (never affects visibility), a half-step rating 1 to 10 (`NULL` clears), and the explicit flag that allows public display. The album rating is separate and is never derived from them.
- **Three different things.** *Saved privately* (flag off), *set to show* (flag on, nothing public yet), *public* (flag on, text in a language whose version is published). The studio says which in words, and the flag alone never makes anything public: a draft or private journal and an unpublished translation stay private.
- **Version rule.** Every save bumps `entries.version` under the entry lock and refuses a stale one.
- **Confirmed change.** A save that adds or edits what a reader sees of a public journal (longer or **shorter** text, a cleared field, a rating, a mark, a flag turned on, text added to a flagged reflection in a public language) needs a `change_public` token for exactly that change, the entry version, and the state stamp. A removal, and a change to what is not public, need none. After the write the rows are read again and any difference from what was confirmed rolls the save back.
- **Interim.** There is no preview action and no dialog, so the studio never obtains or forwards a confirmation and refuses such a save (`published`) until M2.3. The text stays in the editor.

## Checks run on the final head

Run from a clean tree, with the disposable test database up (`pnpm db:test:up`). Results are in the pull request's handoff comment, with the exact head SHA.

```sh
pnpm format:check && pnpm lint && pnpm typecheck
pnpm test                # unit, including the static scans and their probes
pnpm test:integration    # real PostgreSQL, including the concurrency tests
pnpm build && pnpm test:http
pnpm exec playwright test     # desktop, 390 px, axe
pnpm audit --prod
```

## Mutation checks

Each was made by hand once and had to fail at least one test (ADR 0006 § 13). Made with a script that applies one change, runs the integration (or HTTP) suite, and reverts.

| Mutation | Result |
| --- | --- |
| accept a missing token; ignore the expiry; ignore the fingerprint | killed |
| omit the state stamp from the fingerprint | killed |
| omit the old values from the fingerprint | **survived at first**; killed by a test where a value changes behind the application's back |
| omit the entry version from the fingerprint | equivalent: the token's own `n` claim binds the version and is checked first |
| treat a shorter edit, or a cleared field, as a removal | killed |
| skip the album rating, or a reflection's text, in the delta | killed |
| ask for a removal too | killed |
| skip the nothing-to-publish rule | killed |
| let "still writing" change visibility | killed |
| remove the entry lock from the save | killed |
| do not bump the version | killed |
| let the flag alone show a reflection in the studio | killed |
| ignore the favourite mark when writing; write every text into English | killed |
| make a preview take a lock | killed |
| skip the post-write check | **survived at first** (a second defect was needed to show it); killed by a test that forces a divergence with a temporary trigger |
| forward the confirmation from the studio action | killed by the HTTP suite (it runs the built app: rebuild before running) |

Static-scan probes also caught two things in the scans themselves: a consumer that previews itself was missed, and un-deletes or rating writes through a variable, a spread, or a placeholder were not flagged. Both are fixed and probed.

## Independent reviews

- **Security review** (read-only, a fresh context, the `refrain-security-review` skill): no Critical, High, or Medium finding. Low findings acted on: a forgeable confirmation value (now an opaque type, and only the save may call the gate, by scan), writer-scan bypasses by value shape, `writeReflection` call sites (now scanned, including the order), Unicode white space in a reflection (now blank), and the untested divergence guard (now tested). Noted and accepted: the delta on errors is private writing carried as a non-enumerable property, and a save can be about 20 MB in the worst case against the framework's default body limit.
- **Visual review** (read-only, from screenshots against the V4.4 album editor): one must-fix (no visible focus on the "No rating" radio, fixed) and several should-fixes (copy that overstated what was saved, the hover tint on an open row, the emphasis of the state sentence, the compact rating inline, `aria-controls` on a closed row; all fixed). Left as is, on purpose: the 14 px width of a half star, which the design system documents as an exception inside a 44 px row.

## The overlap seen in the review screenshots

The first review screenshots showed "Skip to the content" and the sticky action bar in the middle of the writing area, and the open track's chevron as a hook. **This was a capture artifact, not a defect of the page.** A full-page screenshot paints fixed and sticky elements where the last scroll left them: the review script had clicked a track, which scrolled the page about 1,000 px, so the bar was painted at that offset and the skip link, which waits above the screen by design, fell inside the canvas. The chevron was caught while its 200 ms rotation was still running.

What was checked in a real browser, at 1280 px and 390 px, before concluding that:

- The skip link's box stays above the screen (about −86 to −89 px) at every scroll position, after a pointer click, and at the very bottom; the first Tab brings it to the top of the screen, and the second Tab hides it again.
- The sticky bar sits at the top of the screen while scrolling, and a field focused from far below lands clear of it (field top 455 px against a bar that ends at 98 px at 1280; 435 against 64 at 390).
- Forty Tab and forty Shift+Tab stops through the editor with a track open: none was ever left under the bar.
- The opening sentence is a plain `<input>`: it scrolls inside itself (text 2,315 px wide in a 760 px field; 1,881 px in 355 px at 390), the page has no horizontal overflow, the caret stays in view at the end and while typing, and selection by keyboard and by dragging past the edge works.

Fixed in the capture procedure, not in the application: every full-page capture now starts with nothing focused, the page at the top, and no transition running. The checks are kept as a regression test, [`e2e/editor-journal.spec.ts`](../../e2e/editor-journal.spec.ts); it fails if the skip link stops being hidden, or if the scroll offsets that keep a focused field clear of the bar are removed (both were tried by hand).
