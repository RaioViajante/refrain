### M1 increments

M1 is delivered in increments, each authorized separately by the author:

- **M1.1 — Application foundation** (merged, #3): the Next.js and TypeScript application with pnpm and compatibility-checked versions, Docker Compose PostgreSQL 17, a server-only Drizzle client with a connectivity check, Vitest unit and real-PostgreSQL integration tests, and GitHub Actions CI. See [Development](development.md#local-setup).
- **M1.2 — Relational domain** (merged, #5): an isolated, disposable test database with fail-closed safety checks; the full relational schema for ADR 0002 (catalog with reference editions, entries with per-language visibility, album and artist journals, memories, track reflections, ratings, featured journals, slugs) with versioned migrations; the publication predicate and public read queries; the JOIN and aggregate queries; publication history per language version and retention of published slugs after permanent deletion, with transactional commands; integration tests for the constraints, transactions, and the database-level parts of INV-1 to INV-5; [ADR 0003](decisions/0003-relational-schema-conventions.md) (accepted). See [Data Model](data-model.md).
- **Security and engineering skills foundation** (authorized by the author before M1.3; issue #7): [`SECURITY.md`](../SECURITY.md); implemented and planned protections recorded separately, with a public-release gate, in [Security](security.md#implemented-and-planned-protections); and two Claude Code skills, `/refrain-security-review` and `/refrain-db-change` ([`CLAUDE.md`](../CLAUDE.md#skills)). It includes no application features and no migrations.
- **M1.3A — Identity and authorization** (authorized by the author; issue #9): Better Auth 1.7.12 on PostgreSQL and Drizzle with migration 0004; the single author account, created only by a local command, with public sign-up disabled at all times; database sessions, sign-in, sign-out, and sign-in rate limiting; the fail-closed authorization boundary and the [authorization contract](security.md#authorization-contract) for later work; a minimal sign-in page and protected studio entry point; integration tests and HTTP tests of the production build; [ADR 0004](decisions/0004-single-author-identity.md) (accepted). This brings the "Better Auth single author" part of M2 forward.
- **M1.3B — Catalog and album-journal CRUD** (authorized by the author; issue #15): transactional catalog commands (artists, albums with their reference edition and ordered credits, tracks, ordered tracklists; archive, restore, guarded delete) and album-journal commands (create as a private draft with a reserved slug, save with the `entries.version` check, draft or private only, soft delete); Server Actions that each authorize first; the desk, artists, albums, tracks, and journals screens with plain-text writing stored as the accepted Tiptap document; the JOIN, aggregate, and subquery surfaced in the UI; a real multi-connection slug-race test; HTTP tests that call every Server Action with and without a session; [evidence](evidence/m1-3b.md). No migration. **Deliberately not built:** publishing controls, public pages, restoring a journal and "Delete now" (the owner has since accepted the restoration policy below; both are still to be built), track reflections, ratings, margin notes, translations, featuring, external providers, Tiptap. Status: merged (#16).

- **M1.3C — Recovery, browser tests, and academic verification** (authorized by the author; issue #18; merged, #19): restoring an album journal from a private *Recently deleted* page under the owner-accepted policy ([ADR 0005](decisions/0005-restoring-deleted-journals.md), accepted), with no schema change and no permanent-delete control; a maintained Playwright suite (Chromium, the production build, the disposable database, a synthetic author, a fixed port, desktop and 390 px) that also runs in CI; a backup tool and a restore check that restores an archive into a scratch database and compares it with its source (`pnpm db:backup`, `pnpm db:backup:verify`); reproducible [evidence](evidence/m1-3c.md) for AC-01 to AC-06; two rendering defects that only a browser exposed, fixed (the new-album form and the track pages failed in the production build; an add-track select widened the page on a phone). No migration. **Catalog edit concurrency is not resolved**: see [below](#catalog-edit-concurrency-last-write-wins). **Deliberately not built:** publishing controls, public pages, "Delete now", automatic purge, track reflections, Tiptap, external providers, translations.

- **M2.1 — Command boundary** (authorized by the author; issue #27; merged, #28): the safe publication boundary specified by [ADR 0006](decisions/0006-publication-decision-and-acknowledgement.md), backend only. The Identity module signs and verifies confirmation tokens (HKDF-SHA-256 key from `BETTER_AUTH_SECRET`, HMAC-SHA-256, 15 minutes by the database clock, bound to the author's session, the entry, the language, `entries.version`, and a fingerprint of the disclosure). `previewPublication` reads the disclosure from the real database state, with the same SQL as the public queries (the predicate fragments are parameterized by status, in their own reviewed commit), and mints the token. The checked `publishLanguageVersion(db, author, {entryId, locale, expectedVersion, confirmation})` is the only way to make a version public; the unchecked signature is gone, the write of `published` is not exported, and static scans enforce the allowlist of writers, the export surface, and the no-mint-and-consume rule. `unpublishLanguageVersion` takes the author. Interim, fail-closed: `saveAlbumJournal` refused a published version (`published_text_locked`) until the confirmed save of M2.2 existed; M2.2 replaces that refusal. No migration, no new dependency, no Studio action, no public route. **Deliberately not built in M2.1:** `previewPublicChange` and the confirmed save, reflection and rating editing (built in M2.2), the dialogs and Server Actions (M2.3), "Delete now" (M2.4), the public-reads switch (M3.1). Gates G1 to G8 stay open.

- **M2.2 — Track-by-track writing and confirmed changes** (authorized by the author; issue #29; merged, #30): the album-journal save becomes the data model's boundary 3 (text, album rating, and any number of track reflections in one transaction, under the entry lock, with the `entries.version` check and bump); a reflection has its text per language, the favourite mark (per journal, no limit), "still writing", a half-step rating, and the explicit flag that allows public display, none of which makes anything public by itself; `previewPublicChange` and the confirmed save of [ADR 0006 § 5](decisions/0006-publication-decision-and-acknowledgement.md#5-changes-after-publication) (a `change_public` token bound to the exact exposure delta, the entry version, and the state stamp, through the M2.1 Identity infrastructure); and the Writing Studio's *Track by track* section in the V4.4 style. **Interim, fail closed:** there is no preview action and no dialog, so the studio never obtains a confirmation, never forwards one from a request, and refuses a save that would change a public page until M2.3. No migration, no new dependency. **Deliberately not built:** the publish and change dialogs and their Server Actions (M2.3), "Delete now" (M2.4), translations authoring, Tiptap, memories and artist journals, public routes. Gates G1 to G8 stay open.
- **M2.3 — Studio publication and confirmation workflows** (authorized by the author; issue #31; merged, #32): the private Writing Studio experience for [ADR 0006](decisions/0006-publication-decision-and-acknowledgement.md). Per-language-version **Publish…** opens a dialog that reads a *preview* (the opening sentence, the reflection, the address, the album rating, every track reflection that will be public with its track and language, and what stays private), and publishes only when the author presses its confirm control, with the token that the preview returned; the review changes nothing, and the way to change which reflections are shown is the track editor, then a new review. **Unpublish…** asks first and keeps the writing, the history, and the address. Saving a change to a published journal first asks the server what would change and shows it, before and after, in a confirmation dialog ("Update published writing?"); the confirmed save sends the `change_public` token only from that dialog's confirm control. Two Server Actions that mint tokens (each alone in its file), the checked publish action, and the confirmed save action; the Journals module wraps the Publication engine and checks the entry's kind. Restore and Recently deleted copy now describes the built flow. A single revalidation module is the seam for later; **no public cache exists and public invalidation is not built or claimed** ([ADR 0006 § 11](decisions/0006-publication-decision-and-acknowledgement.md#11-public-reads-and-caches)). No migration, no new dependency, no public route, no public-reads switch. **Deliberately not built:** "Delete now" (M2.4), the address-change dialog, translations authoring, public pages and the public-reads switch (M3.1), Brazilian Portuguese strings. Gates G1 to G8 stay open, and the catalog-wording gap (C11) stays explicit. Evidence: [M2.3](evidence/m2-3.md).

- **M3.1 — First public reading experience** (authorized by the author; issue #34; merged, #35; **local only: nothing is deployed and no gate is closed**): the first anonymous, read-only album-journal page, `/albums/<slug>`, in the approved V4.4 "Grace" layout, read only through the Publication module. A spike on the production build settled how a real status is sent ([Evidence](evidence/m3-1.md#routing-and-http-spike)): the status of a public address is decided in `src/proxy.ts` before any page renders (`404`, `308`, `405`, `503`, all `no-store`), because a page under Cache Components answers `200` and streams a redirect or a not-found view. `REFRAIN_PUBLIC_READS_ENABLED` (server-only, off unless exactly `true`, read at request time) gates the page, the proxy, the sitemap, and `robots.txt`; it can hide content and never reveal it. A second Publication entry point, `public.ts`, exports reads only. The page shows the album, credits, facts, the opening sentence, the album rating, the allow-listed body, the margin note, and only the track reflections that are explicitly public, with the favourite circle and the "still writing" label; artwork is a graceful fallback until the provider integrations exist. Nothing journal-related is cached and no journal data is in the build output. `no-store` is on every response class except the framework's repeated-slash `308`, below. The only prerendered output is a generic, data-free shell, as amendment A2 allows. Every state change is shown on the next request. Tests: unit, a 384-state PostgreSQL oracle, an anonymous HTTP matrix with the switch unset and set to near-miss values, state transitions with the real commands, static scans, and browser tests at desktop width and at 390 px with axe. The studio's copy that said public pages do not exist (#33) now says when a page opens. After the owner's first review the branch also gained a skip link, the author's approved 404 drawing on the shared not-found view, a structural check of the switch, a runtime switch check in the reading entry point, tighter guard tests, and a measured analysis of the cache-hit marker and the prerendered shell. In the final review the owner approved [ADR 0006 amendment A2](decisions/0006-publication-decision-and-acknowledgement.md#a2-the-frameworks-cache-marker-and-the-generic-prerendered-shell), which clarifies both narrowly, the 404 artwork as a narrow exception to the homepage-only character rule, and an optimized WebP of it (467 KB, lossless transparency). The trailing-slash `308` now carries `no-store`. The framework's repeated-slash `308` cannot and is left open for the owner ([evidence](evidence/m3-1.md#owner-review-of-pr-35-the-cache-hit-marker-the-shell-and-the-guards)). No migration, no new dependency. **Deliberately not built:** hosting, the album and artist lists, artist journals, memories, the homepage, the language selector, `pt-BR` interface strings, cover images, music-provider integrations, and M2.4. **Gates G1 to G8 stay open**, each with its state in [Evidence](evidence/m3-1.md#public-release-gates); G8 (catalog wording) and G3 and G4 (out-of-process writers) are not touched.

**Acceptance of PR 2A (restructure, no functional change).**

- Every English address, status, header, body, and metadata value is as it was; `/pt` does not exist yet, and no user-visible text changes.
- The English not-found view keeps its words: `global-not-found` answers an address that is not served, with the real `404` and `no-store` in every request form, and `(en)/not-found.tsx` renders the same view for a page's own `notFound()`. This is measured first on the real proxy, in every request form; if it does not hold, the work stops and is reported.
- **Named checks of the proxy, the cache, and the alternative routes.** Before any route moves, a build with the new tree is compared with the previous `main` over raw HTTP: status, every header, the cache policy (`Cache-Control`, `no-store`, the framework's cache markers), metadata, and visible text, for each public and private address, anonymous and signed in, with public reads off and on. The request forms are `GET`, `HEAD`, `POST`, conditional and range requests, the router's `rsc`, prefetch, and segment-prefetch requests, `.rsc`, `.json`, `.segments`, and `/_next/data`. ### Catalog edit concurrency (last write wins)

Artists, albums, and tracks have no version counter. Two tabs that each loaded the same record and then saved can overwrite each other's named fields: the second save wins, silently. Journal text is protected (`entries.version`, a stale save is refused as a conflict); catalog metadata is not, and **nothing in the interface claims otherwise**.

- **Why it was not fixed in M1.3C.** A correct fix is optimistic concurrency like the journal's: an additive migration adding `version integer NOT NULL DEFAULT 1` (with a `CHECK (version >= 1)`) to `artists`, `albums`, and `tracks`; a required `expectedVersion` on `updateArtist`, `updateAlbum`, and `updateTrack` (an optional one would leave last-write-wins in place for any caller that omitted it, and present it as protection); the three forms carrying the version and showing the existing conflict message; and changes to about fifty test call sites plus the HTTP tests. A token based on `updated_at` would avoid the migration but has the same call-site cost and is weaker. That is a focused change, but not one to rush into the same pull request as restoration, the browser suite, and the backup tool.
- **What it can and cannot damage.** It can overwrite a title, a year, a label, a sort name, a credit list, or a tracklist order with a stale value. It cannot touch the author's writing: journals, their versions, and their slugs are separate, and a catalog record that writing refers to is never deleted.
- **Follow-up.** One small pull request after M1.3C: the migration above (through `/refrain-db-change`, tested on a fresh and an upgraded database), the required `expectedVersion`, the form changes, and conflict tests over real connections. Until then, edit one catalog record in one tab at a time.

### ADR 0005 condition for the M2 publishing interface

Required by the owner in the M1.3C review, clarified on 2026-11-01, and recorded in [ADR 0005 § 5](decisions/0005-restoring-deleted-journals.md#5-required-condition-for-the-m2-publishing-interface), which is the authoritative text. A restore keeps each track reflection's own publication flag, so when a language version is published again after being unpublished, deleted, or restored, reflections that were flagged earlier would become public with it. M2's publishing **system** (any interface, script, bulk operation, or API that publishes or republishes a journal language version) **must not allow that silently**. Whenever publishing may expose individual track reflections, it must:

1. determine the exact set of reflections that would become public, per language (flag set and text in that language);
2. disclose that set to the author, identifying each reflection and its language;
3. let the author review or change individual publication selections;
4. require explicit acknowledgement of the effective set;
5. **enforce that acknowledgement at the Publication command boundary**, not only in the UI;
6. reject missing, outdated, or mismatched acknowledgements when the effective set has changed;
7. check this **atomically** with the visibility change, so nothing can fall between confirmation and publication;
8. apply to **every caller**, with no path around it;
9. never expose a previously published reflection as an undisclosed side effect of publishing the parent version.

Versioned acknowledgements or an equivalent concurrency-safe mechanism may be used; no command signature is fixed yet, and the design is reviewed with M2. **Accepted design (the command boundary is merged in M2.1, the confirmed save in M2.2, and the studio dialogs are merged in M2.3, #32):** [ADR 0006](decisions/0006-publication-decision-and-acknowledgement.md) (issue #25, accepted by the owner on 2026-11-01) specifies a stateless, server-authenticated (MAC) confirmation token bound to the author's session, the entry version, the locale, and the disclosed set, with a table showing how each of the nine requirements is met. The token is evidence of a server-issued disclosure, not proof that the author acknowledged it. ADR 0005 § 5 remains the authoritative requirement either way.

Status: M2.1 built the command boundary that enforces this (a token for the exact disclosure, checked under the entry lock), M2.2 lets the studio set a reflection's flag (which makes nothing public by itself), and M2.3 (merged, #32) adds the studio's publishing control, whose dialog lists every reflection that will be shown with its track and language, never saves anything itself (to change which reflections are shown the author goes to the track editor and reviews again), and publishes only on the author's confirmation. M2 is not done until M2.4 exists, and it is accepted for local use only (gates G1 to G8 stay open). Tests must show, at the command boundary and not only through the UI, that a reflection flagged before a restore does not become public without a matching acknowledgement, and that a stale or mismatched acknowledgement is refused.

## Critical path

AC-01 to AC-06 depend only on **M1**. M2 and M3 deliver the product, but the academic presentation must not depend on them. If time runs short, cut in this order:

1. External integrations (catalog entry remains manual).
2. Author translations and artist journals (translations are not a blocker for the first public demonstration, by the author's decision of 2026-11-01).
3. Visual polish beyond the core layout and typography.
4. Rich-text editing. A plain textarea storing the same structured format is acceptable temporarily.

Never cut database integrity, CRUD, the SQL evidence, privacy protections, or recoverable deletion. By the owner's decision of 2026-11-10, the English and Brazilian Portuguese interface is not on this list either: if it needs more time, secondary polish is cut first, and review and tests are never shortened.
